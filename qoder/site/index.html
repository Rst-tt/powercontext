它解决什么

学习里最耗时的不是「再看一遍」，而是不知道「该看哪一段、上次错在哪」。

01

资料散，找不到出处

几十篇笔记与论文，复习时只记得「好像在哪看过」。知新把资料切成段存入 seekdb，用语义 + 关键词双通道找回原文，并显示命中出处。

02

错过的还会再错

同一个概念第三次答错，但没人提醒你。知新把薄弱点写进 PowerContext，下一轮优先出、优先讲，并在顶部显示「已注入的记忆」。

03

工具不懂你的偏好

有人要先看定义，有人要先看反例。偏好写进记忆后每轮生效；也可以随时在记忆面板「修正」「失效」，不必重启重来。

一轮复习发生什么

检索决定复习范围，记忆决定顺序与提示；作答结果再写回记忆，闭环成立。

  1. 导入资料 seekdb 笔记按 420 字切段，写入 coach_materials（向量列 + 全文列 + HNSW / ngram 索引）。
  2. 组装本轮上下文 PowerContext context/prepare 把偏好与薄弱点拼成本轮上下文，界面显示注入的字节数。
  3. 混合检索选卡 seekdb 同一句 SQL 的两个分支：l2_distance ... APPROXIMATE 走向量，MATCH ... AGAINST 走全文，RRF 融合后排出本轮卡片。
  4. 作答与判题 从笔记里挖空、给出四个选项；判定后在原文里回显命中片段，让学习者立刻回看证据。
  5. 写回记忆 PowerContext 答错时把「课程 / 概念 / 第几次仍然答错」写入记忆；同一段笔记的旧薄弱点先失效再写新条目，避免越积越多。

技术分工

两者不互相替代：检索结果只有作答后才可能变成记忆，记忆只影响下一轮检索与提示。

技术在项目里做什么怎么核对
seekdb
嵌入式（pylibseekdb）		 唯一的资料存储与检索：建表、HNSW 向量索引、ngram 全文索引、混合检索、掌握度与复习次数回写。 界面右栏「seekdb 执行记录」逐条显示真实 SQL、行数、耗时；/api/evidence 可导出。
PowerContext
嵌入式 Server（HTTP API）		 学习者记忆：写薄弱点/偏好/进度，召回并组装上下文；修正与失效走 atomic-memory/lifecycle。 界面右栏「PowerContext 读写」显示每次请求/响应；记忆面板显示条目状态与版本。

运行方式

主通道 Linux / macOS / WSL；Windows 自动降级为 SQLite 镜像后端，界面与流程一致。

# 1) 依赖（主通道）
python3 -m venv .venv && source .venv/bin/activate
pip install -r qoder/requirements.txt

# 2) 启动（嵌入式 seekdb + 嵌入式 PowerContext，无需外部服务）
qoder/scripts/start.sh            # 打开 http://127.0.0.1:8848

# 3) 一键验证（11 个检查点）
python qoder/scripts/smoke.py --base-url http://127.0.0.1:8848

# 4) 离线单元测试
pip install -r qoder/requirements-dev.txt && cd qoder && pytest -q tests

Windows：qoder\scripts\start.ps1。没有 API Key 也能完整运行；配置 OpenAI 兼容的 embedding / LLM 才会启用语义向量与 LLM 讲评。 配置项与接口见仓库 README.md 第 7、8 节。

开源与复用

用到的开源项目

PowerContext（Apache-2.0）提供记忆与上下文服务； OceanBase seekdb（Apache-2.0）与 pyobvector 提供嵌入式向量/全文检索。 本项目在它们之上实现学习教练业务，未修改上游代码。

数据与隐私

所有资料与记忆默认只落在本机 COACH_DATA_DIR；仓库不包含任何 API Key、账号或用户数据。 示例资料为项目自编的学习笔记。
